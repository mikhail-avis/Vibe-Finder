# Hosting Vibe Finder updates on GitHub

## Status and access

**Target repository:** https://github.com/mikhail-avis/Vibe-Finder. The update configuration is pre-set to its public GitHub Raw feed. The updater will only be live once both the release ZIP and the manifest are published.

### Repository

1. The target repository is `mikhail-avis/Vibe-Finder` (public).
2. **Visibility matters:** source code is public. The simple, no-login updater uses public `raw.githubusercontent.com` URLs. For private source code, use a separate public release/feed repository or a private authenticated delivery approach instead; **never put a personal access token inside the app**.
3. Grant the ChatGPT GitHub app access to the repository if you want the assistant to edit it later.
4. Put this project's source files in its **main** branch. Do not upload any personal music, `.venv`, `.env`, secrets, or `updates` data.

### Connect an already-installed Vibe Finder v0.3 to the public repo

Existing v0.3 installs may still have a null URL. If so, edit `C:\AI\Vibe-Finder\update-source.json` (or your actual installation folder):

```json
{
  "manifest_url": "https://raw.githubusercontent.com/mikhail-avis/Vibe-Finder/main/releases/latest.json"
}
```

New installations from this repository are preconfigured. This file is **protected by the updater**, so later updates won't overwrite it. The 'Check for online updates' button checks when clicked, not silently in the background.

### Publish a new version

1. Make changes to app source and tests; increase `APP_VERSION` in `version.py` (e.g. `0.4.0`). Never re-use a published version number.
2. Run: `python -m unittest discover -s tests -v`.
3. Build the custom update package (GitHub's autogenerated source ZIP is NOT a valid app update):

   `python scripts/build_release.py --owner mikhail-avis --repo Vibe-Finder`

4. Commit `releases/vX.Y.Z.zip` to the public repo, then commit the generated `releases/latest.json`. The manifest is intentionally published **last**.
5. On the Windows app, open **App updates → Check for online updates → Download and prepare update**. Close the app and relaunch using `run-windows.bat`. It updates in place, keeping the `library` and `.venv` folders.

The ZIP and JSON are both served from `raw.githubusercontent.com` to satisfy the existing updater's same-host security rule. Check the `sha256` against the final ZIP; the packager does this. The release ZIP is expected to remain under 50 MB (GitHub's regular-file repository limits may be more restrictive at larger scales).

### Current scope and important caveats

- This is *not yet* fully automatic installation; checking, downloading and restarting are user-triggered in v0.3.
- The online update feed is not live until the repository exists, the files are pushed, and `update-source.json` is configured.
- GitHub authentication isn't required on the client **only for public release files**.
- HTTPS and SHA-256 detect accidental corruption and some tampering, but the hash **alone is not a cryptographic publisher signature**: anyone who controls the repository/feed can replace both. Review releases before publishing; for a broadly distributed app, add signed updates and an independent trust anchor.
- No website publishing or local PC changes are performed by this package.
