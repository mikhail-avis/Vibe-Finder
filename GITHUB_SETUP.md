# Publishing Vibe Finder to GitHub

The repository is configured as the public update host, but an update is **not live** until the application source, custom release ZIP, and release manifest are published.

## Source package
The prepared package is named `Vibe-Finder-GitHub-Publish-Package.zip`. Extract it and upload the contents (not the enclosing ZIP alone) to the root of the repository. Never upload `library/` audio, `.venv`, credentials, or personal user data.

## Update hosting
The desktop app reads `update-source.json`, which points to:
`https://raw.githubusercontent.com/mikhail-avis/Vibe-Finder/main/releases/latest.json`

Publish the custom `releases/vX.Y.Z.zip` **before** publishing `releases/latest.json`. A manifest without its ZIP would present a broken update. Do not use GitHub's autogenerated source archive as the update ZIP.

Each future update must increment `APP_VERSION` in `version.py`. Run `python -m unittest discover -s tests -v`, then `python scripts/build_release.py --owner mikhail-avis --repo Vibe-Finder`, and publish the generated archive before its manifest.

The app's online-update check is user-triggered. Applying an update requires restarting through `run-windows.bat`. Existing personal music and virtual environment must remain untouched. Desktop behavior still needs testing on Windows.
